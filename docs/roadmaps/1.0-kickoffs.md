## 0. Conventions the prompts assume

- **The plan is on main** since PR #228 merged (2026-08-28, `648dbab6`); the `git show docs/forge-1-0-blueprint:<path>` fallbacks still written in the prompts are inert. PR #228 ignores `_1.0/`.
- **Lane launch (T1 does it; 1.0.md §1.3).** `lanes.sh render docs/roadmaps/1.0-kickoffs.md '^## N\. <lane>' /home/parso/forge/_1.0/prompts/<lane>.md [PARAM=VALUE]`, then `lanes.sh launch /home/parso/forge/_1.0 <lane> /home/parso/forge/_1.0/prompts/<lane>.md --open` (model opus, permission-mode auto, cwd the main checkout — the lane cuts its own worktree). tmux session `forge-<lane>`; operator: `tmux attach -t forge-<lane>`, detach `C-b d`. T1 answers a park with `SendMessage(to: "forge-<lane>", notify_when_idle: true)` (e.g. `approved: H2 run 1, ceiling $20`), watches with a persistent Monitor on `lanes.sh events /home/parso/forge/_1.0` (`lanes.sh list` / `peek` are for diagnosis), retires with `lanes.sh kill`. A lane that needs the operator parks: it writes the artifact and the ledger line, sends `PARK <lane>: …` to T1's session and ends its turn; the ruling arrives as a cross-session message. Lanes cannot `AskUserQuestion` (a launch-time hook blocks it; story sessions are launched `--attended`); the operator answers only in T1's session.
- **Detached jobs (verify-cycle, story runs, CI watches).** Launch detached (`setsid nohup … > /home/parso/forge/_1.0/reports/<lane>-<job>.log 2>&1 < /dev/null &`, PID in the ledger) **and in the same step start a background waiter** (`until ! kill -0 <PID>; do sleep 30; done`, run in the background) so the job's completion wakes you — a lane that ends its turn after a detached launch does not wake by itself (2 h lost on a passing run, 2026-08-28). While it runs, heartbeat every ≤ 10 min from the job's own log and declare that log in `/home/parso/forge/_1.0/heartbeat/<lane>.liveness` (one path/glob per line) so the stall watcher judges you by the job, not your silence. Never `pgrep -f` a string your own prompt contains (it self-matches); use `pgrep -x node` + `/proc/<pid>/cmdline`.
- **Parameters.** Three prompts carry a `PARAMETER` first line (T1: `MILESTONE`; M1-C: `STORY`; M4: `PKG`). Replace the value on that line before pasting; the body refers to it as `$MILESTONE` / `$STORY` / `$PKG`.
- **Lane ids, worktrees, branches.** Lane id = milestone-letter, lower-case (`m0-a`); in M4 the lane id is the package name. Worktree `~/forge-<lane>` (`~/forge-m0-a`, `~/forge-knowledge`), branch `<milestone>/<letter|pkg>` (`m0/a`, `m4/knowledge`), always cut from `parsoFish/main`. Two exceptions state their reason inline (T1 works on `main` in the main checkout; M0-B commits nothing to forge). Clean-checkout gates use `~/forge-clean-<lane>` so `git worktree list` sees them.
- **Campaign state** is `/home/parso/forge/_1.0/` (gitignored). A gitignored dir is not shared into worktrees, so every lane writes ledger/briefs/plans/manifests/cull there by **absolute path**. Two additions to §1.2's layout: `_1.0/heartbeat/<lane>.log` (stall watcher input) and `docs/roadmaps/1.0-kickoffs.md` (this file, tracked).
- **Gate manifests (immutable-gates), one format:** `_1.0/gate-manifests/<lane>.txt` = repo-relative **paths only**, one per line (test files, `package.json`, CI config, fixtures, story files). Content pins go beside it: `<lane>.sha256` (`xargs -a <lane>.txt sha256sum > <lane>.sha256`, verified with `sha256sum -c`) and `<lane>.counts` (test counts, LOC). Restore = `git restore --source=<pin> --pathspec-from-file=/home/parso/forge/_1.0/gate-manifests/<lane>.txt` — one git command, no `git checkout`, no `.`.
- **Bridge rule for every story or verify-cycle run.** `scripts/verify-cycle.mjs` *reuses* any healthy bridge on 4123/4124 and the old journey harness *force-takes-over*; both would test the wrong tree. So: `curl -s localhost:4123/api/health` → if `{service:'forge-bridge',pid,…}` answers, `readlink /proc/<pid>/cwd` must be **your worktree**; if it is another checkout, stop and ask the operator to close that session — never `--force-takeover`. When 4123 is free the run boots its own bridge from your worktree.
- **Brain.** 1.0.md §1.1 fixes the read order and the brain is not in it; `brain-query` is forge's product skill under `skills/`, not one a lane invokes. CLAUDE.md's brain-first rule is suspended for this campaign by that read order.
- **Merge protocol (every PR):** strict branch protection → `gh pr update-branch <n>` → CI green for the PR's current head SHA (`gh pr checks <n>` shows `success`, never "no checks reported") → merge → re-verify merged main with `npm run build && npm test`. Never `--admin`. Never `git add -A`. `git checkout` never shares a command line and never takes `.`. Fix PRs inside a lane are cut from `parsoFish/main`, never stacked on the lane branch.
- **Installs — run before the session that needs them (skills and MCP servers are discovered at session start).** The cached `pr-review-toolkit`, `claude-md-management` and `commit-commands` copies are registered to the project path `/mnt/c/Users/David`, not to this repo or user scope, so `/plugin enable` has nothing to enable here — use `/plugin install <name>@claude-plugins-official` (user scope, enables on install): `pr-review-toolkit` (M0-A, M4; its `silent-failure-hunter` is an **agent** you dispatch, plus `/pr-review-toolkit:review-pr`) · `claude-md-management` (M0-C) · `commit-commands` (M1-A, `/clean_gone` only) · `plugin-dev` (M4-library) · `session-report` (every T2, at lane close). Playwright MCP for M1-C only, pinned without the plugin: `claude mcp add --scope local playwright -- npx -y @playwright/mcp@0.0.79`, removed after (`claude mcp remove playwright`). Skill files copied to user scope before the session: `loop-design-check` (M5-A: `/plugin marketplace update ecc && cp -r ~/.claude/plugins/marketplaces/ecc/skills/loop-design-check ~/.claude/skills/`) · `documentation-writer` (M6-B: `mkdir -p ~/.claude/skills/documentation-writer && gh api repos/github/awesome-copilot/contents/skills/documentation-writer/SKILL.md --jq .content | base64 -d > ~/.claude/skills/documentation-writer/SKILL.md`). npm: `dependency-cruiser` (named by the plan for M2-A; disclosed in the PR title) · `knip` (M6-C proposal only — parks). **Never enable:** `ralph-loop` (unrelated to `loops/` Ralph; its Stop-hook loop conflicts with the out-of-process watcher), `security-guidance`/`semgrep` (per-edit hooks, network installs), the `ecc` plugin as a whole (23 hooks), `forge-refinement` from M2 on (hard-codes the pre-package layout).
- **H3 exception.** If M0 records "tail unproven; M5 rebuilds it", the G1 re-proof rows of M2-B, M3 and M4-flows are recorded NOT MET *citing that ruling* and do not block the next milestone — that deferral is H3's own default. Every other NOT MET blocks.
