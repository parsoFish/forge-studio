# Forge 1.0 — the plan

> **For agentic workers:** this is the single roadmap for all forge work from 2026-08-28 until the 1.0 tag. R1–R8 in this directory are reference only and are archived in M6. Every session that works this plan runs under the `tiered-orchestration` skill with file-durable state in `_1.0/` (gitignored). Per-milestone implementation plans are written **at that milestone's kickoff** with `superpowers:writing-plans` — never in advance — because each milestone's file-level tasks depend on the previous milestone's measured outcome. Steps use `- [ ]` syntax for tracking in `_1.0/ledger.md`.

**Goal:** ship forge-studio 1.0 — a software factory construction platform packaged along its real seams, with the weight deleted, one deletable example factory, and nine operator stories that run green as live proof, demo, and usage documentation at once.

**Architecture:** strangler in place (Approach A + grafts): same repo, npm workspaces `packages/*` + `apps/*`, a dependency-cruiser allow-graph enforced as a ratchet, `git mv` with history, every milestone exit certified by a real merge on a real ground. No microservices. The OOTB develop flow becomes `@forge/factory`, redesigned last, deletable.

**Spec:** [`docs/superpowers/specs/2026-08-28-forge-1-0-blueprint-design.md`](../superpowers/specs/2026-08-28-forge-1-0-blueprint-design.md) — the plan argues from it; read both. Visual companion: <https://claude.ai/code/artifact/2559035a-2e09-4f75-b42c-b03f32b6dbf6>.

**Status:** in progress — M0 opened 2026-08-28 by a T1 session following §1; campaign state lives in `_1.0/` (§1.2). Operator decisions D1–D3 are recorded in the spec §0 and are not reopened here.

## Global constraints (verbatim from the spec; every task inherits them)

- Name: **forge-studio**. Licence: **AGPL-3.0-or-later**. Install form for 1.0: **Node source checkout**. Supported platform: **WSL2 / Linux**. "ideas machine" and "forge v2" are retired everywhere.
- **No microservices.** No network boundary between packages. The only future candidate for process isolation is untrusted community-hook execution in `library`, on a concrete driver only.
- Allow-graph: `contracts ← kernel ← {library, knowledge, projects} ← agents ← sessions ← flows ← factory ← apps/{forge, studio}`; `apps/studio` imports `contracts` only; packages never import `orchestrator/ cli/ loops/`; legacy imports a package only via `orchestrator/_pkg/<pkg>.ts`.
- File hard cap **800 lines**, enforced by lint from M2. Per-package LOC caps recorded in `QUARRY.md` at M2.
- Live model calls never block a PR. `verify-cycle.mjs` is operator-gated and never runs in CI. Never `--project mdtoc`.
- Merge protocol: strict branch protection → `gh pr update-branch` → CI green on the exact head → merge → re-verify merged main with build + typecheck + full `npm test`. Never `--admin`. Never `git add -A`. `git checkout` never shares a command line and never takes `.`.
- One session = one lane = one package (or one named cross-cutting concern). Lanes work in their own worktree at `~/forge-<lane>`; `_worktrees/` is for ground repos only.
- Campaign residue lives only in `_1.0/` (gitignored). A permanent artifact (ADR, this roadmap, `docs/`) never cites a path inside it.
- Every exit criterion names (a) the lane that delivers it, (b) the producing route/agent/story beat, (c) the command proving it. Nothing is marked met by absence of red.
- Every milestone ends with one real run on a real ground, or its exit table records NOT MET.

### 1.2 The campaign substrate (`_1.0/`, gitignored)

```

├── briefs/<M>-<lane>.md  goal, exact gate commands, acceptance-test placement, deletion duties, park points, size budget, max attempts
```

Gate manifests use one format: `<lane>.txt` = repo-relative paths, one per line; `<lane>.sha256` beside it (`sha256sum -c`); counts in `<lane>.counts`. Restore = `git restore --source=<pin> --pathspec-from-file=_1.0/gate-manifests/<lane>.txt` (never `git checkout` with a path list on the same line).

Success test for the substrate: a successor with zero conversation history resumes correctly from these files alone.

### 1.3 Tiers and lanes

| Tier | Runs | Owns | Never |
|---|---|---|---|
| T1 — campaign orchestrator | one per milestone, light model | sequencing, briefs, lane launch + relay (tmux), rulings, milestone exit gate, ledger | implements; trusts a claim without running the gate |
| T2 — lane orchestrator | one per lane, strong model — a fresh `claude` session in tmux `forge-<lane>`, launched by T1; the operator attaches to interact | decompose → pin tests → spawn T3 → run every gate itself → PR → merge → ledger | carries another lane's state |
| T3 — workers | fresh context each | test-writing, implementing, adversarial review, spec-only brief | reads the wider campaign |

Rules that were measured to matter (see `tiered-orchestration`): file-scoped red→green, full suite once at the gate; gate-run waivers need a recorded `git diff` proof; suite-runners never overlap editors in one tree; commit worker output on arrival; a heartbeat carries real state; the stall watcher lives out of process; two reopenings of the same defect class means the class is misdiagnosed — stop and re-plan.

**Lane mechanism (adopted 2026-08-28).** Lanes are neither sessions the operator pastes by hand nor T1's in-process subagents — subagents cannot nest, so a T2-as-subagent would lose its T3 fan-out and do everything in one context. T1 renders each lane's kickoff prompt from `1.0-kickoffs.md` to `_1.0/prompts/<lane>.md` and launches it with `.claude/skills/tiered-orchestration/scripts/lanes.sh launch`: a fresh `claude --model opus --permission-mode auto` session in a detached tmux session `forge-<lane>`, cwd the main checkout (the lane cuts its own worktree), pane piped to `_1.0/heartbeat/<lane>.tmux.log`, and a Windows Terminal tab opened on it (`--open`). The operator attaches with `tmux attach -t forge-<lane>` (detach `C-b d`). T1 watches with `lanes.sh peek` / `lanes.sh list`, relays park-point rulings with `lanes.sh send <lane> '<ruling>'`, and launches a dependent lane only after re-deriving its predecessor's exit rows. The cron stall watcher is `scripts/watch-heartbeats.sh _1.0/heartbeat`.

## 2. The cull stance (operator mandate, 2026-08-28)

**Assume nothing is good.** Every component has room to become lighter and to drop guardrails. Tightening runs to date added cruft because agents worked from an instruction layer full of it. Therefore:

1. **The instruction layer is culled first (M0)**, before any code moves: `CLAUDE.md`, the 29 `SKILL.md`s, the ten current-state docs that still narrate the unifier, and the brain's one-shot campaign notes. A fresh session must not be able to learn a poor practice from the repo's own instructions.
2. **Every guard must justify itself or die.** Each lane keeps a cull ledger (`_1.0/cull/<pkg>.md`): for every lint, allowlist, ratchet, parity test, golden, journey beat, doc page and config knob it touches — `keep` requires the incident (`_wave*/ledger.md`, a brain theme, a `_1.0/traces/` file) or the story it protects; otherwise `cut`. "It might catch something" is not a reason. The 29 security allowlist ratchets and the ~53 two-sided parity tests are presumed keep; everything else is presumed cut until justified.
3. **Guardrail budget.** A package may not add a new guard without retiring one of equal or greater weight in the same PR, unless the guard closes a reproduced incident recorded in the ledger.
4. **Fewer, real gates.** The operator's stories (§3) and the real-ground merges are the gates. Seeded emulation is deleted once the story that replaces it is green.
5. **Briefs are spec-only.** A T3 brief cites the spec, the package README and the story; it never says "follow the existing pattern in X" where X is legacy code.
6. **Measured, not attributed.** A lane's PR body carries its LOC delta (prod, test, docs) and its cull ledger summary. Milestone exit tables carry the totals. Weight that grows is a finding.

One script yields three artifacts: the e2e verdict, the demo clip and frames, and the usage-doc fragment (tutorial or how-to) — so the tests, the demos and the docs cannot drift from each other. The current `scripts/e2e-journey.mjs` + `scripts/journeys/*` harness is **replaced, not collapsed** (M1 builds the successor; M6 deletes the old one).

### 3.1 Story harness v2 (built in M1, owned by the `stories` lane)

Requirements, not implementation (the M1 lane writes the plan):

- One story = one file under `tests/stories/<id>.story.mjs`: `beats[]` with `{ act: 'operator does X', expect: { route, data: {...} }, say: 'narration' }`; a `ground` declaration (project id, whether a real spawn happens, its budget); a `docs: { kind: 'tutorial'|'how-to', title }` header.

Gallery index derived, never hand-edited.
- Real spawns are the default where the flow needs an agent; `ground.budget_usd` is enforced through the existing kickoff-ceiling path; a story that needs money declares it and the runner refuses to start without `--approve-spend`.
- No seeded state except what a **prior beat** created in the same story; fixtures are named by the story that owns them and swept by the story's last beat (crash-safe leading sweep retained from the current harness — the one part worth keeping).
- Host lock, port identity, memory preflight and commit-first are inherited from the current harness's measured lessons. Bridge rule: a healthy bridge on 4123 is reused only if `readlink /proc/<pid>/cwd` is the lane's own worktree (today `verify-cycle.mjs` reuses any healthy bridge and the journey harness force-takes-over — both would test the wrong tree).
- `npm run stories -- --story S5` runs one; `npm run stories` runs all; CI runs the stories that cost nothing; a costed story declares `ground.budget_usd` and refuses to start without `--approve-spend` (H2) — there is no "costless beats only" mode.
