## 3. Fill in the name, the quality gate and the north star — and under Advanced, the repo path — then press "Onboard project →"

Registering the project lands the operator on its page, where forge immediately measures GitWeave against the project contract and reports the result honestly: a hard fail. Registration scaffolds the contract artifacts forge can write without asking anyone, so the checklist says contract — present, and preflight says hard fail, and both are true at once: a scaffolded contract is a stub, not an answer. The secrets, demo and roadmap stages have nothing at all; only the instructions carry real content, read from the repo's own CLAUDE.md. No Flow can be pointed at a project in this state.

## 4. Open "Brief the agent", give it the north star and the gate command, and press "Run onboarding agent"

The operator does not fill the contract in by hand. An Agent does it, briefed with the three things only the operator knows: what the project is for, the command that tells the truth about whether it works, and what it must not touch. One press asks and answers — the brief travels through the same question form every other session kind publishes, and the run id appears only once an agent is really running.
