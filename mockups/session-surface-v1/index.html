Locked decisions (inputs to this set — context, not up for comment)

  • L1Model selection is a spawn-time tier choice inside the SKILL-declared range. Kickoff writes modelTier to session status.json; resolveSessionModel(spec, requestedTier?) validates in-range and throws naming the allowed set. strategy: fixed skills render a read-only model chip — no picker.
  • L2The working feed is visible. Full thinking is streamed and shown, capped per block with expand; tool-use rows carry the tool + its target; redacted_thinking renders as a literal [thinking redacted] row.
  • L3Demo builder gets a dedicated session screen — on this same generic surface, like instructions. Its inline project-page panel and the /demo/[sid] redirect stub retire.
  • L4Every kind kicks off from the same screen at /sessions/[kind]/new — kind differences are data (descriptor + SKILL.md), not layout.
  • L5Affordances are derived, not authored (ADR-043): a structured phase ⇒ question form; an awaiting-* phase ⇒ verdict; a staging write ⇒ staged-file review. The panels in these mockups each cite the phase-table row they fall out of.
